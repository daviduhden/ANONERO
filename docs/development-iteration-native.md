# Native snapshot hardening — 2026-11-14

## Threat model recorded before editing

Asset: complete and correctly typed transaction/output snapshots, process integrity,
and wallet context isolation at JNI. A malformed native object, resource exhaustion,
or Kotlin constructor contract drift can make object construction fail. Existing list
conversion clears exceptions and skips failed entries, producing an apparently valid
partial snapshot. Coin-control decisions and transaction history must not silently use
incomplete native data.

Boundary: wallet2 objects → C++ adapter → JVM model constructors → Kotlin snapshots.
Change: fail an entire snapshot on conversion failure, retain JNI exceptions, release
local references with existing RAII, catch C++ exceptions at refresh exports, and throw
a fixed Java error if a failed conversion supplies no JVM exception. Preserve all
transaction, output-selection, fee, key, consensus, and persisted-format semantics.

Failure if wrong: omitted outputs/history or native crash. Residual limits: opaque
handles remain lifetime-dependent; this is not overall JNI memory-safety proof. Null
transfer lists remain valid only when wallet2 reports no transfers. No JNI export name,
method signature or model field order changes. CI needs both flavors/ABIs and injected
allocation/constructor/wallet2 failures, confirming no partial snapshot publication.
Rollback: revert adapter/checker changes; no stored-data migration is required.

## Static regression scope

Extend the existing JNI parity script to validate the four project model constructor
parameter types/order against descriptors used by GetMethodID. This is a deliberately
bounded parser: unsupported types or syntax fail closed; generated bytecode, linkage,
default-argument constructor overloads and actual JNI invocation still require CI.

## Deferred lifetime finding

`Wallet_setListenerJ` deletes the previous adapter before detaching wallet2's listener.
Moving the detach alone cannot prove in-flight callbacks have finished: the upstream
implementation is unavailable locally. A complete fix needs callback quiescence and
coordinated Kotlin close/replace semantics. No claim of resolved listener lifetime safety
is made by this increment.

## Close exception containment

Before changing close: `WalletManager_closeJ` invalidates handles and releases listener
references only when wallet2 reports success. An uncaught C++ exception currently crosses
JNI. Preserve ownership on false/exception and report false with a fixed diagnostic;
Kotlin must retain failed-close wrappers rather than forget them. The adapter cannot
prove upstream exception guarantees from the unpopulated submodule. CI must inject a
close failure before destruction and verify retry/handle retention; arbitrary upstream
partial-destruction exceptions remain an independent native lifetime risk.
